# Prosessikuvaus QA audit — 2026-09-07

## Purpose

This audit treats the current Prosessikuvaus implementation as a product under hostile/realistic testing rather than assuming the happy-path examples are representative. The goal is to discover failure modes before more UI/features are layered on top.

The standalone v0.6.0 implementation remains the behavioural baseline while VakeTomate migration continues.

## Automated baseline executed

Standalone v0.6.0 regression suite: **22/22 passed**.

It covers numbered/un-numbered Finnish input, flattened clipboard input, Markdown, Unicode hyphens, gibberish rejection, system/document semantics, TKKI aliasing, passive research-permit prose, VTR 1–13, edit-state persistence, summary semantics and DrawIO generation.

An additional adversarial/fuzz harness was run locally against the v0.6.0 engine:

- 500 clipboard/input mutations across numbering, bullets, line flattening, Unicode separators, zero-width characters and XML-sensitive characters;
- normalization idempotence;
- XML escaping;
- empty/gibberish export safety;
- 75-step stress process;
- filename bounds/safety;
- NBSP/Unicode normalization.

Result: **7/7 QA harness groups passed without crashes**.

Passing crash/fuzz tests does **not** mean the semantic output is always correct. The following semantic/workflow defects were discovered.

## Confirmed defects / risks

### P0 — wrong actor inheritance when verb vocabulary misses a verb

Examples such as:

- `Hankinta-asiantuntija tekee hankintatapa-arvion`
- `IT-arkkitehti suunnittelee integraation`
- `Asiantuntija tunnistaa tarpeen`

can retain the step but inherit the previous actor because the finite verb is outside the parser's current verb list. In unnumbered prose such actions can be dropped entirely.

**Required fix:** broaden process-verb recognition and add a conservative finite-verb fallback. An explicit apparent actor at the beginning of a numbered step must never silently inherit a previous actor merely because the verb dictionary missed the verb.

### P0 — manual symbol/type edit can revert

If an automatically detected `system` node is manually changed to `activity`, normalization can infer `system` again and overwrite the user's decision.

**Required fix:** distinguish `type_source=auto|manual` (or equivalent lock) and never re-infer a manual override.

### P0 — unsafe automatic Finnish imperative

Current deterministic conversion can produce invalid Finnish such as:

- `Laatii rahoitushakemuksen` → `Laadi rahoitushakemuksen`
- `Tarkastaa hakemuksen` → `Tarkasta hakemuksen`

This is worse than leaving the source wording for human review.

**Required fix:** deterministic transformation must be conservative. Only generate an imperative when the complete phrase transformation is known safe; otherwise preserve source wording and mark the suggestion as needing review.

### P1 — ordinary unnumbered multiple-process headings can merge

Two process sections with normal mixed-case headings and unnumbered action lines can be treated as one section.

**Required fix:** section detection should use blank-line context + next-action evidence, while avoiding earlier false positives where action sentences became headings.

### P1 — canonical actor invariant is not enforced by `addActor`

`addActor` currently allows direct callers to create both `TKKI` and `TKKI-yksikkö`. Only legacy migration canonicalizes them.

**Required fix:** canonicalization belongs inside the canonical model boundary.

### P1 — reorder API can desynchronize visual order from graph flow

`reorderLinearNodes()` sorts `nodes[]` but leaves sequence edges untouched.

**Required fix:** replace/augment with `reorderLinearFlow()` that rewires a truly linear graph and refuses branch graphs rather than corrupting semantics.

### P1 — validation lacks global graph reachability

Local `incoming/outgoing` checks do not detect a disconnected cycle that is unreachable from the process start.

**Required fix:** validate reachability from the unique start and ability to reach the unique end.

### P1 — decision validation is incomplete

Outgoing count alone is insufficient. Branch labels can be empty or duplicated.

**Required fix:** detect missing/duplicate conditional labels; prefer explicit `Kyllä/Ei` for binary decisions when appropriate.

### P1 — data-flow label requirement is not validated

VAKE guidance requires the information moving to/from a system to be named on a data-flow arrow.

**Required fix:** warn when a `data_flow` edge has no information label.

### P0/P1 — approval authorization and revision safety

Shared approval workflow currently allows:

- submission without a resolved approver;
- approval by an arbitrary actor unless the caller prevents it;
- content changes after submission without binding the decision to the reviewed revision;
- stale rejection/decision fields across resubmission;
- end-of-month drift when adding review months with native `setMonth`.

**Required fix:** enforce approver identity, revision binding, clean resubmission state and end-of-month-safe date arithmetic.

### P1 — draft source text can be lost before parsing

In the browser reference app, changing source text is not equivalent to changing the parsed model. Reloading before parsing can lose the draft source.

**Required fix:** autosave the source draft independently from the parsed canonical model.

### P1 — actor edit can overwrite richer phase responsibility

A change of swimlane actor can overwrite a manually enriched responsibility field that also mentions assisting/informed roles.

**Required fix:** update phase responsibility automatically only if it is blank or still exactly equal to the previous lane actor.

### P2 — missing-field counter can overstate incompleteness

Traceable information can legitimately be not applicable for some phases, but the current UI can count it as universally missing.

**Required fix:** distinguish required, optional, not-applicable and unreviewed fields.

### P1 — owner-review readiness is currently too permissive

`qualitySummary.ready_for_owner_review` only blocks on `error`. A process with major summary fields empty can therefore appear ready.

**Required fix:** create a separate submission-readiness gate that checks core organizational fields and confirmed responsibility without turning every optional field into an error.

### P2 — browser download URL revocation can race

The shared `BrowserDownloadAdapter` revokes object URLs immediately after `.click()`; some browsers may not have consumed the URL yet.

**Required fix:** revoke after a short delay / next task.

## Product-quality invariants to add to CI

1. No user edit is silently rewritten by normalization.
2. No explicit actor is replaced by the previous actor because a verb was unknown.
3. Canonical actor aliases cannot coexist as separate swimlanes.
4. Every non-start/end node is reachable from start and can reach end unless explicitly marked as an intentional terminal/subprocess boundary.
5. Graph reorder operations cannot change semantics accidentally.
6. Approval decision is bound to the exact revision submitted.
7. Only the configured approver/authorized substitute can decide an approval.
8. Parser never fabricates an organizational fact to make validation green.
9. Deterministic language transformations never knowingly produce grammatically unsafe wording.
10. UI complexity is progressive: primary workflow stays small; advanced fields remain available without being always visible.
